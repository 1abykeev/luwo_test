# Backend checklist

Source tags are explained in `standards-sources.md`. "Project" means a decision recorded in `CLAUDE.md`.

## Layering and dependency inversion
- [ ] Agent, tools and services import no SQLAlchemy, asyncpg or Postgres type. Check with `grep -rn "sqlalchemy\|asyncpg" app/agent app/tools app/services app/api`. *Why:* the main task requirement is that only the adapter and the composition root change when the data source changes. [Cosmic: repository, dependency inversion] (Allowed: `app/repositories/postgres`, `app/db`, `app/container.py`, and the stores in `app/agent/memory.py` and `app/observability/request_log.py`, which are the agent's own state: project.)
- [ ] The data source is chosen in one place (`app/container.py`). *Why:* swapping to REST/MCP must be a one-branch change. [Cosmic]
- [ ] Repository interfaces are small and return domain objects (dataclasses), not ORM rows. *Why:* ORM objects leaking upward break the in-memory adapter and a future REST adapter. [Cosmic]
- [ ] The in-memory adapter honours the same contract as Postgres (scope filters, ordering, soft delete, case-insensitive search). *Why:* the same tests must pass on both; a behavior difference means one adapter lies.

## Services and permissions
- [ ] Every permission rule lives in `app/services/permissions.py` or an action's `plan()`, and is reached from every tool path. *Why:* the prompt is not a security layer (project). [OWASP-API API1, API5]
- [ ] Every id supplied by a user or the model (student, teacher, class, token) is authorised against the actor, not just looked up. Another school's id answers "not found", not "forbidden" (project). *Why:* object-level authorization is the top API risk. [OWASP-API API1]
- [ ] Which fields a request may set are limited (no mass assignment of role, school, status). [OWASP-API API3]
- [ ] Services own use-case orchestration; route handlers only parse input and map errors. *Why:* thin entrypoints, testable services. [Cosmic: service layer; FastAPI-BP]

## Transactions and data integrity
- [ ] A change and its history row are written in one transaction (unit of work); an error leaves no partial change. [Cosmic: unit of work]
- [ ] Confirmation uses an atomic claim (`UPDATE ... WHERE status='pending'`), and `plan()` is re-run at confirm time (project).
- [ ] DB constraints back the rules (CHECKs, unique indexes, foreign keys), so a bug in code cannot store bad data.
- [ ] Appends that must keep order (chat messages) cannot collide under concurrency (row lock or retry).

## Async correctness
- [ ] No blocking call inside `async def` (CPU-heavy hashing, sync SDK calls, file or network I/O). Example already fixed: bcrypt in a thread. [FastAPI-BP: async routes]
- [ ] Time limits on external calls (model, database); a request cannot run unbounded. [OWASP-API API4]
- [ ] No module-level side effects on import (the app is built lazily).

## Validation and errors
- [ ] Input constraints are in Pydantic schemas (length, pattern, ranges), not scattered checks. [FastAPI-BP: Pydantic]
- [ ] One error format (`{"error": {"code", "message", "details"}}`) for domain errors, with correct status codes (401, 403, 404, 409, 422, 500); unexpected errors never leak internals.
- [ ] Settings come from the environment with a startup guard for dangerous defaults. [12F: config]

## Migrations (Alembic)
- [ ] Each migration has a working `downgrade`, and a descriptive name. [FastAPI-BP: migrations]
- [ ] New NOT NULL columns on existing tables carry a `server_default` or a backfill (own knowledge). *Why:* an autogenerated migration fails on a table with rows.
- [ ] Models and migrations agree (`alembic check`, read-only); there is a single head (`alembic heads`).
- [ ] Indexes exist for the common filters (student by class, name search, history by entity, request log by time and type).

## Performance
- [ ] N+1 queries in loops over classes or teachers (known and deferred in `CLAUDE.md`: do not re-report unless the load-test numbers show a problem).
- [ ] Unbounded result sets are capped (search results, history length).
